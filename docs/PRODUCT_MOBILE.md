# Produto Mobile — Hotel Empire

## 1. Visão

Hotel Empire Mobile é um tycoon de hotel com simulação sistêmica e progressão de longo prazo.

O jogador começa dentro da operação e termina acima dela.

```
operador
→ funcionário multifunção
→ chefe de equipe
→ gerente
→ dono
→ franqueador
→ império
```

## 2. Objetivo de produto

Criar um jogo mobile:

- acessível em sessões curtas;
- profundo o suficiente para recompensar planejamento;
- com progressão de semanas/meses;
- monetizado por conveniência, velocidade e expressão;
- sem depender de frustração artificial;
- expansível por hotéis/mapas.

## 3. Early game

O jogador inicia com:

- hotel pequeno;
- pouco cash;
- nenhuma equipe;
- poucos quartos;
- recepção simples.

Tarefas manuais iniciais:

- check-in;
- limpeza;
- room service;
- reparos simples;
- atendimento de situações especiais.

Essas ações devem ser rápidas e claras. O objetivo é gerar vínculo com a operação e tornar a contratação significativa.

## 4. Transição para gestão

A primeira grande recompensa é deixar de precisar executar tudo.

```
fazer tarefa
→ contratar
→ delegar
→ otimizar
→ supervisionar
```

O jogador continua podendo agir manualmente quando houver gargalo.

## 5. Staff

Papéis candidatos:

- recepção;
- limpeza;
- manutenção;
- cozinha;
- garçom;
- segurança;
- concierge;
- técnico;
- supervisão;
- gestão.

Funcionários possuem:

- nível;
- XP;
- salário;
- eficiência;
- qualidade;
- traits limitados.

A versão inicial deve lançar com poucos papéis bem diferenciados.

## 6. Construção e upgrades

Construção não é instantânea.

Tempos devem crescer junto da importância, sem transformar a experiência em espera permanente.

Referência de curva:

- onboarding: 10–60 s;
- early: 1–5 min;
- mid: 5–30 min;
- late: 1–4 h apenas em investimentos relevantes.

Cada construção pode:

- concluir naturalmente;
- receber redução via rewarded;
- ser concluída/avançada com Gems;
- usar speedup ganho.

## 7. Slots

O jogador começa com capacidade limitada de construção simultânea.

Slots extras podem vir de:

- progressão;
- objetivo;
- premium;
- evento.

Não bloquear totalmente o jogo por falta de slot.

## 8. Upgrades e especializações

Salas podem evoluir até N5 quando o conteúdo justificar.

Além de valores maiores, upgrades devem produzir identidade.

Exemplo:

### Quarto Executivo

- tarifa maior;
- afinidade business;
- maior exigência de serviço.

### Quarto Conforto

- maior satisfação;
- estadias mais longas.

### Quarto Econômico

- menor manutenção;
- maior taxa de ocupação;
- ticket menor.

## 9. Estrelas

Cada hotel progride de uma a cinco estrelas.

Estrelas sintetizam:

- reputação;
- ocupação;
- satisfação;
- rentabilidade;
- variedade de serviços;
- eficiência;
- objetivos especiais.

A subida de estrela deve desbloquear conteúdo e alterar visual/status do hotel.

## 10. Missões

### Principais

Guiam a progressão daquele hotel.

### Secundárias

Recompensam otimização e exploração de sistemas.

### Diárias

Curta duração e baixa fricção.

### Semanais

Metas maiores.

### Evento

Ligadas a conteúdo temporário.

Season Missions ficam para fase posterior.

## 11. Offline

Enquanto o jogador está fora:

- construções avançam;
- upgrades avançam;
- hotel gera resultado agregado;
- custos continuam;
- ocorrências relevantes podem ser resumidas.

Ao retornar:

```
Receita
Custos
Lucro
Construções concluídas
Eventos relevantes
```

Pode haver rewarded para melhorar a recompensa offline, sem transformar o valor base em punição.

## 12. Reservas antecipadas

O jogo deve oferecer demanda futura.

Exemplo:

```
TechCon
42 hóspedes
chegada: amanhã
receita potencial: alta
```

O jogador avalia:

- quartos;
- recepção;
- alimentação;
- elevadores;
- equipe;
- manutenção.

Aceitar uma reserva é assumir compromisso operacional.

## 13. Eventos

Categorias:

- infraestrutura;
- demanda;
- segurança;
- reputação;
- clima;
- turismo;
- grupos especiais.

Exemplos:

- inspeção sanitária;
- apagão;
- vazamento;
- elevador quebrado;
- festival;
- congresso;
- casamento;
- celebridade;
- temporada alta/baixa.

## 15. Reviews

Reviews são geradas a partir da simulação.

Variáveis:

- espera;
- limpeza;
- alimentação;
- conforto;
- preço;
- elevadores;
- atendimento;
- incidentes.

Reviews devem ser legíveis e explicar causas.

## 16. Room Service

Room service usa sistemas reais:

- origem do pedido;
- preparação;
- funcionário;
- caminho;
- elevador;
- entrega;
- satisfação;
- receita.

Aumentar vendas pode piorar gargalos se a operação não acompanhar.

## 17. Manutenção

Infraestrutura sofre desgaste.

Alvos iniciais:

- elevador;
- cozinha;
- ar-condicionado;
- gerador;
- instalações.

Manutenção preventiva reduz risco de falhas.

## 19. Prestige / Franquia

Ao completar um hotel, o jogador pode franquear/vender.

Recebe Empire Points.

Mantém:

- progresso permanente;
- bônus de rede;
- cosméticos;
- Gems;
- entitlements.

Recomeça economicamente em novo contexto.

## 20. Pós-lançamento

Features candidatas depois de validação:

- concorrentes;
- contratos avançados;
- Hotel Pass;
- temporadas;
- espionagem/observação profunda;
- privacidade/reputação sistêmica;
- tech tree extensa;
- elevadores especializados;
- multiplayer/social assíncrono futuro, se fizer sentido.

## 21. Métrica de qualidade

Uma feature só entra se melhorar pelo menos um destes e não destruir os outros:

- diversão;
- clareza;
- profundidade;
- retenção;
- monetização saudável;
- performance;
- capacidade de expansão.
